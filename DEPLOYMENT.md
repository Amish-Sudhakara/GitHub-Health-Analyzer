# AWS Deployment & Configuration Guide

This guide details how to deploy **GitHub Student Health Analyzer** to AWS using **AWS Amplify Hosting** for the React frontend and an **AWS Lambda Function URL** for the Python backend.

---

## 1. Architecture & Deployment Workflow

```
┌─────────────────────────────────┐           ┌──────────────────────────────────┐
│          AWS Amplify            │           │        AWS Lambda Backend        │
│       (React Single Page)       │  HTTPS    │     (Python 3.12 Function URL)   │
│  https://main.xxx.amplifyapp.com│──────────>│ https://yyy.lambda-url.aws/      │
└─────────────────────────────────┘           └─────────────────┬────────────────┘
                                                                │
                                                                │ GitHub REST & GraphQL APIs
                                                                ▼
                                                      ┌───────────────────┐
                                                      │    GitHub APIs    │
                                                      └───────────────────┘
```

Because the frontend requires the backend's Lambda Function URL, and the backend requires the frontend's Amplify origin for CORS, follow this **3-step deployment order**:

1. **Deploy Frontend on AWS Amplify** to obtain your frontend origin URL (`https://main.xxx.amplifyapp.com`).
2. **Deploy Backend on AWS Lambda** with a Function URL, setting `ALLOWED_ORIGIN` to your Amplify URL.
3. **Configure `VITE_API_URL` on AWS Amplify** with your Lambda Function URL and trigger a redeploy.

## 2. Configuration Placeholders Reference

When following this guide, replace these placeholders with your actual values:

| Placeholder Variable | Description | Where It Is Configured |
| :--- | :--- | :--- |
| `GITHUB_TOKEN=PASTE_GITHUB_TOKEN_HERE` | GitHub Personal Access Token (classic or fine-grained) | AWS Lambda Environment Variables & Local `.env` |
| `AWS_REGION=PASTE_AWS_REGION_HERE` | AWS Region (e.g., `us-east-1` or `eu-west-1`) | AWS Management Console |
| `ALLOWED_ORIGIN=PASTE_AMPLIFY_URL_HERE` | Allowed CORS origin (e.g., `https://main.d12345.amplifyapp.com`) | AWS Lambda Environment Variables |
| `VITE_API_URL=PASTE_LAMBDA_FUNCTION_URL_HERE` | Public backend Function URL | AWS Amplify Environment Variables & Frontend `.env` |
| `GITHUB_REPOSITORY_URL=PASTE_GITHUB_REPOSITORY_URL_HERE` | Your GitHub repository URL | Local Git Remote & AWS Amplify |

> [!CAUTION]
> Never commit real tokens or credentials to your Git repository. All `.env` files (except `.env.example`) and build artifacts are strictly ignored by `.gitignore`.

## 3. Step 1: Frontend Initial Deployment on AWS Amplify

### 3.1 Push Repository to GitHub
Ensure your project is committed and pushed to GitHub (see [Pushing to GitHub](#7-pushing-project-to-github)).

### 3.2 Connect to AWS Amplify
1. Open the [AWS Management Console](https://console.aws.amazon.com/) and navigate to **AWS Amplify**.
2. Click **Deploy an app** (or **Host web app**).
3. Select **GitHub** as your Git provider and click **Next**.
4. Authenticate with GitHub and select your repository: `GITHUB_REPOSITORY_URL=PASTE_GITHUB_REPOSITORY_URL_HERE`.
5. Select branch `main`.
6. Under **App settings**, Amplify will automatically detect the monorepo configuration from `amplify.yml`:
   - Frontend build command: `cd frontend && npm ci && npm run build`
   - Base directory: `frontend/dist`
7. Click **Next** and **Save and deploy**.
8. Wait for the build to complete. Note the public URL generated by Amplify, for example:
   `https://main.d1a2b3c4d5e6.amplifyapp.com`
   *(This is your `ALLOWED_ORIGIN`)*.

## 4. Step 2: Backend Deployment on AWS Lambda

### 4.1 Create Lambda Function
1. In the AWS Console, navigate to **AWS Lambda** in your preferred region (`AWS_REGION=PASTE_AWS_REGION_HERE`).
2. Click **Create function**.
3. Choose **Author from scratch**:
   - **Function name**: `github-student-health-analyzer`
   - **Runtime**: `Python 3.12`
   - **Architecture**: `x86_64` or `arm64`
4. Click **Create function**.

### 4.2 Upload Backend Code
1. Open the **Code** tab.
2. Open `backend/lambda_function.py` from this repository.
3. Replace the contents of `lambda_function.py` in the Lambda web editor with the code from `backend/lambda_function.py`.
4. Click **Deploy**.

*(Alternatively, you can create a zip containing `lambda_function.py` and upload it via **Upload from -> .zip file**).*

### 4.3 Configure General Settings
1. Navigate to **Configuration** -> **General configuration** -> **Edit**:
   - **Memory**: `128 MB` (or `256 MB` for faster cold starts)
   - **Timeout**: `15 seconds`
2. Click **Save**.

### 4.4 Configure Environment Variables
1. Navigate to **Configuration** -> **Environment variables** -> **Edit**.
2. Add the following key-value pairs:

| Key | Value | Notes |
| :--- | :--- | :--- |
| `GITHUB_TOKEN` | `PASTE_GITHUB_TOKEN_HERE` | Personal Access Token from GitHub (`public_repo` or read-only public access) |
| `ALLOWED_ORIGIN` | `https://main.xxx.amplifyapp.com` | Your Amplify domain from Step 1 (or `*` during initial testing) |

3. Click **Save**.

### 4.5 Configure Lambda Function URL
1. Navigate to **Configuration** -> **Function URL** -> **Create function URL**:
   - **Auth type**: `NONE` (allows public HTTPS access from your frontend).
   - **Configure CORS**:
     - Check **Configure cross-origin resource sharing (CORS)**.
     - **Allow origin**: Enter your Amplify URL (e.g. `https://main.xxx.amplifyapp.com`) or `*`.
     - **Allow methods**: Check `GET` and `OPTIONS`.
     - **Allow headers**: `content-type`, `authorization`, `x-requested-with`.
2. Click **Save**.
3. Copy the generated **Function URL**:
   Example: `https://abc123xyz789.lambda-url.us-east-1.on.aws/`
   *(This is your `VITE_API_URL`)*.

### 4.6 Concurrency & Cost Safeguards
Because the Function URL uses Auth type `NONE`, anyone with the URL could theoretically trigger Lambda execution:
1. Navigate to **Configuration** -> **Concurrency** -> **Edit**.
2. Select **Reserve concurrency** and set it to a low limit such as `3` or `5`.
   - *Explanation*: This bounds concurrent executions to prevent high Lambda usage spikes or accidental GitHub API rate exhaustion.
3. **Operational Recommendation**: If you are not actively demonstrating or grading the project, you can toggle the Function URL to Auth type `AWS_IAM` or delete the Function URL to eliminate unauthenticated requests.

## 5. Step 3: Link Backend to Frontend on Amplify

Now that you have your Lambda Function URL:

1. Return to the **AWS Amplify Console**.
2. Select your `github-student-health` app.
3. In the left navigation, click **Environment variables** (or **App settings** -> **Environment variables**).
4. Click **Manage variables** -> **Add variable**:
   - Variable: `VITE_API_URL`
   - Value: `PASTE_LAMBDA_FUNCTION_URL_HERE` (e.g., `https://abc123xyz789.lambda-url.us-east-1.on.aws`)
5. Click **Save**.
6. Trigger a new frontend build:
   - Go to **Hosting** -> select branch `main` -> click **Run build** (or push an update to your `main` branch).
7. Once the build completes, open your live Amplify application in your browser.

## 6. Verification Checklist

Test your deployed application using this quick checklist:
1. Open your live Amplify URL.
2. Enter `octocat` into the search box and click **Analyze**.
3. Verify that:
   - The loading indicator displays progress messages.
   - Profile information (Avatar, Bio, Followers) renders properly.
   - Statistics cards display active weeks, public repos, and the Activity Rating.
   - Monthly contribution bar chart and 52-week heatmap load accurately.
   - Programming language horizontal chart displays top languages.
   - Up to 10 repositories are listed with Documentation/Maintenance checks.
   - 2-3 deterministic improvement suggestions appear.
   - Clicking **Download Report (PDF)** generates and downloads a clean PDF report.
4. Try an invalid username (e.g. `-invalid`) and verify that user-friendly client-side validation displays.
5. Try a non-existent username (e.g. `user-does-not-exist-9999`) and verify that a 404 alert box appears.

## 7. Cost Control, Budgets & Monitoring

### 7.1 AWS Budgets & Free Tier Notice
AWS costs depend on account status, current regional pricing, and usage. While lightweight student projects generally fall well within AWS Free Tier limits (1 million Lambda invocations/month and 1,000 Amplify build minutes/month for the first 12 months), **AWS is not guaranteed to be permanently free**.

### 7.2 Set an AWS Budget
1. In the AWS Console, search for **AWS Budgets**.
2. Click **Create budget** -> **Cost budget** (Recommended).
3. Set a monthly budget of **$1.00** or **$5.00 USD**.
4. Set threshold alerts at 80% and 100% with your student email address.
5. Click **Create budget**.

### 7.3 CloudWatch Log Retention
By default, Lambda CloudWatch Logs retain logs indefinitely, which can accumulate small storage charges over months.
1. Navigate to **CloudWatch** -> **Logs** -> **Log groups**.
2. Locate `/aws/lambda/github-student-health-analyzer`.
3. Click **Actions** -> **Edit retention setting**.
4. Change retention from *Never expire* to **7 days** or **14 days**.
5. Click **Save**.

## 8. Pushing Project to GitHub

To push this project to your GitHub repository for the first time:

```bash
# 1. Initialize git (if not already done)
git init

# 2. Stage all files
git add .

# 3. Create your initial commit
git commit -m "feat: complete GitHub Student Health Analyzer project"

# 4. Set default branch to main
git branch -M main

# 5. Link your remote GitHub repository
git remote add origin PASTE_GITHUB_REPOSITORY_URL_HERE

# 6. Push to GitHub
git push -u origin main
```

Subsequent pushes to `main` will automatically trigger a new frontend deployment on AWS Amplify. Any updates to `backend/lambda_function.py` should be updated in the AWS Lambda Console.
